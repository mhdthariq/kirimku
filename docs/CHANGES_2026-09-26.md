# Changes in this pass (2026-09-26)

## Bug fixes
1. **B2B customer display (company name first, PIC second).** New shared
   helper `src/lib/customer-display.ts`. Applied to: Customers page list,
   shipment list rows, shipment detail header/cards, the customer picker in
   shipment creation, and the selected-customer summary card. Also fixed a
   systemic backend bug where `gudang`, `dashboard`, `dashboard/kurir`,
   `pickups`, `deliveries`, and `transports` endpoints were sending the PIC
   name instead of the company name for B2B customers.
2. **Gudang coordinates → one paste field.** New
   `src/components/app/coordinate-paste-field.tsx` + `src/lib/coordinates.ts`
   parse whatever you paste from Google Maps (decimal or DMS) into lat/lng.
   Wired into the Gudang create/edit dialog, replacing the two separate
   Latitude/Longitude inputs.
3. **Map tiles: OSM → Google Maps.** `src/components/app/leaflet-picker.tsx`
   now renders Google Maps roadmap tiles (still via Leaflet, per your
   instruction to swap tiles only — no Maps API key wired in). Note: Google's
   terms technically expect the official Maps JavaScript API/billed key for
   production tile usage — flagging this so you can revisit if it matters
   for your deployment.
4. **Pickup & Delivery coordinates.** `latitude`/`longitude` added to both
   models (migration:
   `prisma/migrations/20260926120000_pickup_delivery_coords_and_b2b_pricing/`),
   exposed through the pickups/deliveries APIs, and editable via the same
   coordinate-paste field in both create/edit dialogs.
5. **Kurir task map.** New `src/components/app/task-points-map.tsx` — a
   read-only map on the kurir dashboard plotting every pickup (RED) and
   delivery (GREEN) that has coordinates set, with popups showing the
   code/address.

## New features
6. **B2B pricing methods: /kg, /koli, /cubic.** Every `Tariff` now carries a
   `pricingMethod`. B2C (and generic) tariffs are **forced to `/kg`
   server-side** regardless of what's submitted. B2B tariffs can pick `/kg`,
   `/koli`, or `/cubic` in the Tariffs page; picking a tariff at
   shipment-creation time is how the operator picks the method (the
   route/tariff dropdown shows the unit right in the label). The pricing
   engine (`src/lib/pricing.ts`), the `/shipments/{id}/price` endpoint, and
   the shipment detail pricing card are all method-aware.

## Migration required
Run this against your database before deploying:
```
npx prisma migrate deploy
```
(or `npx prisma migrate dev` in development) — the migration is purely
additive (nullable columns / columns with safe defaults), so it's safe to
run without downtime or data loss.
